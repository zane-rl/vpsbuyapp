# 数据库设计

数据库：SQLite，由 Prisma 管理。Schema 定义见 [`prisma/schema.prisma`](../prisma/schema.prisma)。

## 1. 实体关系

```
Customer (1) ───< (N) VpsServer         一个客户有多台 VPS（VPS.customerId 可空，SetNull；新建 VPS 时必选）
Customer (1) ───< (N) CustomerPayment   一个客户有多条收款记录（Cascade）
Customer (1) ───< (N) CustomerRecharge  一个客户有多条充值记录（Cascade，客户级共享余额）
Customer (1) ───< (N) NotifyRecipient   一个客户有多个到期提醒收件人（Cascade；customerId 为空=全局收件人）
Customer (1) ───< (N) NotifyLog         一个客户有多条推送记录（Cascade，每天至多一条）
Provider (1) ───< (N) VpsServer         一个提供商被多台 VPS 引用（VPS.providerId 可空，SetNull）
VpsServer (1) ───< (N) VpsRenewal       一台 VPS 有多条续费记录（Cascade）
VpsServer (1) ───< (N) VpnNode          一台 VPS 有多个 VPN 节点（Cascade）
```

- 删除 VPS 时，其续费记录与节点级联删除。
- 删除客户时，其收款记录、充值记录、到期提醒收件人与推送记录级联删除，名下 VPS 的 `customerId` 置空。
- 删除提供商时，引用它的 VPS 的 `providerId` 置空。
- 自动续费 VPS 的余额改为**客户级共享**（`CustomerRecharge`）：名下所有 auto VPS 共用该客户余额；当前余额取最近一条充值的 `balanceAfter`。原 `VpsBalanceLog` / `VpsServer.balanceAmount` 已弃用（保留列避免线上重建表）。

## 2. 表结构

### 2.0 `Provider`（提供商，单独维护）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String(cuid) | ✓ | 主键 |
| `name` | String | ✓ | 名称，唯一 |
| `createdAt` | DateTime | ✓ | 创建时间 |

### 2.0b `Customer`（客户）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String(cuid) | ✓ | 主键 |
| `name` | String | ✓ | 名称，唯一 |
| `note` | String? | | 备注 |
| `createdAt` / `updatedAt` | DateTime | ✓ | 时间戳 |

### 2.0c `CustomerPayment`（客户收款记录，独立台账）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String(cuid) | ✓ | 主键 |
| `customerId` | String | ✓ | 外键 → Customer，级联删除 |
| `amountCny` | Float | ✓(默认0) | 本次收款金额（CNY） |
| `payDate` | DateTime | ✓(默认now) | 收款时间 |
| `paymentProof` | String? | | 实际收款截图（`data/uploads/` 下文件名） |
| `note` | String? | | 备注（付款方式/覆盖哪些 VPS） |
| `createdAt` | DateTime | ✓ | 创建时间 |

### 2.0d `CustomerRecharge`（客户充值记录，客户级共享余额）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String(cuid) | ✓ | 主键 |
| `customerId` | String | ✓ | 外键 → Customer，级联删除，建索引 |
| `amountUsd` | Float | ✓(默认0) | 本次充值（USD，计入总成本） |
| `paidCny` | Float | ✓(默认0) | 本次实际付款（CNY，计入总实付/差额） |
| `balanceAfter` | Float | ✓(默认0) | 充值后服务商实际余额（USD）；作为余额估算的基准（base） |
| `rechargeDate` | DateTime | ✓(默认now) | 充值时间 |
| `paymentProof` | String? | | 付款截图（`data/uploads/` 下文件名） |
| `note` | String? | | 备注 |
| `createdAt` | DateTime | ✓ | 创建时间 |

> 给客户自动续费 VPS 的预充值。名下所有 auto VPS 共享该余额。**当前余额为估算值**：以最近一条 `balanceAfter` 为基准，减去名下各 auto VPS 按「`cyclePriceUsd` ÷ 周期天数」折算的日均消耗 × 已过整天数；并据此推算「预估到期/耗尽日」。估算逻辑见 `src/lib/billing.ts` 的 `estimateSharedBalance`。

| --- | --- | --- | --- |
| `id` | String(cuid) | ✓ | 主键 |
| `name` | String | ✓ | 备注名/标识，如 "香港-01" |
| `customerId` | String? | | 外键 → Customer（SetNull），建索引 |
| `providerId` | String? | | 外键 → Provider（SetNull），建索引 |
| `cpu` | String? | | 如 "2 vCPU" |
| `ram` | String? | | 如 "2 GB" |
| `disk` | String? | | 如 "55 GB SSD" |
| `bandwidth` | String? | | 如 "2 TB/月" |
| `region` | String? | | 地区，如 "香港" |
| `ipAddress` | String? | | IP 地址 |
| `os` | String? | | 操作系统，如 "Ubuntu 24.04" |
| `billingType` | String | ✓(默认term) | 计费类型：`term`(固定期限) / `auto`(自动续费) |
| `termPeriod` | String? | | 仅 term：购买周期 `monthly` / `quarterly` / `yearly`（用于按购买时间自动推算到期） |
| `autoCycle` | String? | | 仅 auto：`hourly` / `monthly` / `quarterly` / `yearly` |
| `cyclePriceUsd` | Float? | | 仅 auto：周期费用（USD）；用于估算日均消耗、共享余额与预估到期 |
| `balanceAmount` | Float? | | **已弃用**：余额改为客户级共享（`CustomerRecharge`），保留列避免线上重建表 |
| `purchaseDate` | DateTime | ✓ | 购买时间 |
| `expiryDate` | DateTime? | | 到期时间（term 必填、auto 为空；续费时更新为最新值），建索引 |
| `purchaseCostUsd` | Float | ✓(默认0) | 采购成本（USD） |
| `purchasePaidCny` | Float | ✓(默认0) | 购买实际付款（CNY） |
| `paymentProof` | String? | | 实际付款截图（`data/uploads/` 下的文件名） |
| `status` | String | ✓(默认active) | 运行状态：`active` / `stopped` |
| `notes` | String? | | 备注 |
| `createdAt` | DateTime | ✓ | 创建时间 |
| `updatedAt` | DateTime | ✓ | 更新时间 |

> 是否"过期"不入库，由 `expiryDate` 在运行时实时计算。

### 2.4 `NotifySetting`（到期推送设置，单例行）

固定一行，`id` 恒为 `"default"`。放数据库而非环境变量，改配置无需重启服务。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String | 是 | 固定 `"default"` |
| `enabled` | Boolean | 是 | 推送总开关，默认 `false` |
| `botToken` | String? | 否 | Telegram Bot Token；启用时必填 |
| `daysAhead` | Int | 是 | 剩余多少天开始推送，默认 `5` |
| `siteBaseUrl` | String? | 否 | 站点公网地址，用于拼客户专属查看链接的绝对 URL；启用时必填 |
| `updatedAt` | DateTime | 是 | 更新时间 |

> **为什么站点地址要入库**：定时任务从 `localhost` 调用推送端点，请求头里取不到公网域名，必须显式配置。

### 2.5 `NotifyRecipient`（推送收件人）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String | 是 | cuid |
| `customerId` | String? | 否 | **有值 = 该客户专属收件人**（只收自己服务器的提醒）；**为空 = 全局收件人**（通常是管理员，收所有客户的提醒） |
| `chatId` | String | 是 | Telegram chat_id，纯数字，群组为负数 |
| `label` | String? | 否 | 备注，如「张三」「运维群」 |
| `enabled` | Boolean | 是 | 停用后不再接收，默认 `true` |
| `createdAt` | DateTime | 是 | 创建时间 |

- 唯一约束 `@@unique([customerId, chatId])`：同一客户下 chat_id 不重复；不同客户可用相同 chat_id。
- SQLite 唯一约束中 NULL 互不相等，**全局收件人的重复校验在应用层做**（`notify-recipients` 的 POST 里 `findFirst`）。

### 2.6 `NotifyLog`（推送记录，兼作去重依据）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | String | 是 | cuid |
| `customerId` | String | 是 | 归属客户（Cascade） |
| `notifyDate` | DateTime | 是 | 归零到当天 00:00 |
| `reason` | String | 是 | `term` / `auto` / `both` |
| `detail` | String | 是 | 触发明细，如「香港-01 剩 3 天；自动续费余额约 4 天耗尽（估算）」 |
| `sentCount` | Int | 是 | 成功送达的 chat_id 数 |
| `failCount` | Int | 是 | 失败数 |
| `error` | String? | 否 | 失败原因汇总（截断至 500 字符） |
| `createdAt` | DateTime | 是 | 创建时间 |

- 唯一约束 `@@unique([customerId, notifyDate])` 即**去重键**：同一客户同一天只推一次。定时任务重复调用会被跳过；后台「立即检查并推送」用 `force` 走 upsert 覆盖当天记录，便于验证配置。

## 3. 财务汇总口径

收款已从 VPS/续费移到独立的 `CustomerPayment` 台账，充值移到 `CustomerRecharge` 台账。汇总公式：

```
总成本(USD)   = Σ purchaseCostUsd + Σ VpsRenewal.costUsd + Σ CustomerRecharge.amountUsd
总实付成本(CNY) = Σ purchasePaidCny + Σ VpsRenewal.paidCny + Σ CustomerRecharge.paidCny
总收款(CNY)   = Σ CustomerPayment.amountCny
差额(CNY)     = 总收款(CNY) − 总实付成本(CNY)        // 正=盈余/客户多付，负=欠款
（客户充值的 amountUsd 计入总成本、paidCny 计入总实付成本/结算）
```

- **全局**（`src/app/admin/page.tsx`）：对全部 VPS/续费/收款/充值聚合；并提供「按客户统计」表（每客户 总成本$/总实付¥/收款¥/差额¥）。
- **按客户**（`src/app/admin/customers/[id]/page.tsx`、客户列表页）：仅对该客户名下的 VPS/续费/收款/充值聚合；客户详情展示「当前共享余额（估算）」与「预估到期」。
- **客户公开页**（`src/app/view/[customerId]/page.tsx`）：卡片区展示「总购买成本(USD)/总实际付款(CNY)/总收款(CNY)/差额(CNY)」，含自动续费 VPS 时另展示「当前充值余额（估算，USD）」及预估到期。
  - **付款记录表**把 `VpsServer`（购买）、`VpsRenewal`（续费）、`CustomerRecharge`（充值）三类合并成一张按日期倒序的台账，表尾合计 **= 总实付成本(CNY)**，即该客户的整体购买服务器开销。
  - **收款记录表**列出 `CustomerPayment` 每一笔，表尾合计 **= 总收款(CNY)**，并给出「收款 − 实付 = 差额」。两表左右并排（`lg:grid-cols-2`），便于逐笔对账。
  - VPS 卡片内的「实际付款」= 该机 `purchasePaidCny` + 其全部续费 `paidCny`，付款截图统一收敛到付款记录表，不再逐卡展示。
- **共享余额估算口径**：见 `src/lib/billing.ts` `estimateSharedBalance`（基准 `balanceAfter` − 日均消耗 × 已过整天数，预估耗尽日 = 余额 ÷ 日均消耗）。在客户详情、VPS 详情、概览列表、客户公开页四处统一展示。
- 成本以 USD 记录、付款/收款以 CNY 记录；差额只用人民币口径，不做汇率换算。
